## 1. 목적 (Why) — #879 에서 잘못 처리한 것

#879 에서 "US breadth 는 7종목으로 계산할 수 없다"고 **측정해 놓고**, 조치를
**게이트 통과**로 하고 데이터 확보를 "범위 밖"으로 미뤘다. 데이터 공백을 설계 제약으로
취급한 것이 잘못이다 — 표본이 부족하면 **보강해야** 한다(사용자 지적).

배포 후 라이브 로그는 더 나빴다.

```
US 시장상황 신호 없음(표본 0종목 < 100) — 게이트 통과 처리
```

7종목도 아니고 **0종목**이다. US 종목이 100개 이상인 거래일이 아예 없어 집계가 성립하지
않는다 — 즉 **US 는 시장 레짐 신호가 전무한 상태로 매수**됐다.

## 2. breadth 를 US 로 확장하지 않은 이유

`runScan` 은 `universeMapper.findAll()`(KR 전용)을 돌며 **종목당 1 API 콜 + throttle** 이다.
US breadth 를 만들려면 수백 종목을 매일 수집해야 하는데:

- `us_universe` 에는 **`symbol`/`name`/`market` 뿐**이다 — 시총·유동성·섹터가 없어
  "대표 300종목"을 고를 근거가 **DB 에 없다**.
- 12,445종목 전체 백필은 토스 레이트리밋·토큰에 부담이고, 그래도 어느 종목이 대표인지는
  데이터를 쌓은 뒤에야 안다.

## 3. 채택 — SPY 지수 (이미 작동 중인 경로)

`ValuationClient.getIndexReturnPct` 는 야후 차트 API 를 쓰고 **US 상대강세 판정에 이미
쓰이고 있다**. 토스가 US ETF 캔들을 주지 않아(#828 QA 실측: SPY/QQQ/VOO/IVV/DIA 전부
0건) 야후로 우회한 경로이고 작동이 검증됐다.

그리고 `getIndexReturnPct("SPY", 1)` 은 내부적으로 6개월 일별 종가를 받아 **마지막 2개로
계산**하므로 일간 수익률을 그대로 준다 — **새 API 가 필요 없다**.

### 3.1 임계값 캘리브레이션 (실측, 251거래일)

| 분위 | SPY | 연간 차단일 |
|------|-----|-------------|
| 하위 1% | −2.04% | 2일 |
| 하위 2% | −1.70% | 5일 |
| **하위 4%** | **−1.52%** | **10일** |
| 하위 10% | −0.99% | 25일 |
| 최저 / 중앙값 | −2.70% / +0.06% | — |

KR 게이트(breadth ≥ 20%)는 `application.yml` 주석의 분포(최근 25거래일 16.3~69.9%,
중앙값 ≈45%)로 보면 **극단일만 차단**하는 수준이다. 그에 대응하는 값이 **−1.5%**
(하위 4% 분위, 연 10~12일 차단)다. **임계값을 발명하지 않고 KR 과 같은 엄격도로 맞췄다.**

### 3.2 SPY 는 동일가중 사각지대가 있는가 — 측정했고, 없다

**제기한 우려**: SPY 는 시가총액 가중이라 "지수는 멀쩡한데 평균 종목은 빠지는" 국면을
놓칠 수 있다. 실제로 같은 날 한국에서 그 현상을 측정했다(KODEX200 −4.25% vs 동일가중
섹터 평균 +19%).

**측정**: SPY vs RSP(동일가중 S&P500) 250일 일간 수익률, 임계 −1.5%.

| 경우 | 일수 |
|------|------|
| 둘 다 통과 | 238 |
| **SPY만 통과(RSP 차단)** | **0** |
| RSP만 통과(SPY 차단) | 10 |
| 둘 다 차단 | 2 |

**우려는 기각된다.** SPY 가 오히려 더 엄격하다 — 꼬리가 더 두껍다(최저 −2.70% vs
−2.25%, 하위 4% −1.52% vs −1.27%). RSP 를 더해도 게이트가 **느슨해질 뿐** 보호가 늘지
않는다.

> 한국과 달랐던 이유: 한국 괴리는 **3,700종목(소형주 포함)의 20일 누적**이었고, 여기는
> **같은 S&P500 안에서 가중만 다른 1일 수익률**이다. 일간 급락은 가중 방식과 거의 무관하게
> 같이 움직인다. 괴리는 **누적**에서 나타난다 — 1년 SPY +15.3% vs RSP +11.9%(집중도 효과).

따라서 **RSP 를 추가하지 않는다.**

## 4. 설계 — 시장마다 구할 수 있는 신호를 쓴다

| 시장 | 신호 | 임계 |
|------|------|------|
| KR | 전종목 breadth(3,699종목) | `min-breadth-pct` = 20 |
| US | SPY 일간 수익률 | `index-min-daily-pct` = −1.5 |

신호를 못 구하면(조회 실패·표본 부족) **통과**시킨다 — 레짐 신호 부재로 매수가 막히는
것보다 종목별 게이트(저평가·펀더멘털·인기·상대강세·급등필터)에 맡기는 쪽이 낫다.

### 4.1 SPY 로 갈음되는 범위 — 시장 레짐 **하나**다

| 판정 | US 에서 쓰는 것 | 이 이슈로 변경? |
|------|------------------|-----------------|
| 시장 레짐 게이트 | **SPY 일간 수익률** | **신규** |
| 상대강세 | 종목 N일 수익률 vs SPY N일 수익률 | 불변(#828) |
| 인기(거래대금·가격) | 그 종목 `daily_ohlcv` | 불변 |
| 급등 필터 | 그 종목 5일 최저 대비 | 불변 |
| 저평가·펀더멘털 | 종목별 밸류에이션 API | 불변 |

### 4.2 남는 한계 (명시)

SPY 게이트는 **"오늘 급락인가"** 만 본다. 누적 집중도(대형주만 오르는 장)는 보이지 않고,
그 부분은 종목별 **상대강세(SPY 대비)** 가 일부 커버한다.

## 6. 인수조건 / 테스트 (전부 통과, 432건)

1. US 후보는 SPY 로 게이트된다 — `US_판정에_KR_breadth를_조회하지_않는다`
2. SPY 임계 미만이면 US 매수 차단 — `SPY가_임계값_미만이면_US_매수가_막힌다`(−2.7%)
3. 임계 이상이면 진행 — `SPY가_임계값_이상이면_US_매수가_진행된다`(−1.4%)
4. 조회 실패 시 통과 — `SPY_조회_실패시_US_매수는_통과시킨다`
5. KR 은 breadth 로 판정, 결과 불변 — `KR_breadth가_낮으면_KR_후보는_막힌다`
6. 시장당 1회 조회 — `같은_시장_후보가_여러건이어도_breadth는_한번만_조회한다`

**라이브 확인**(2026-10-08 22:40, 미국장 개장 중): SPY 일간 −0.31% → 임계 −1.5% 통과.
이전에는 표본 0종목으로 무조건 통과했으므로, **실제 지수 값으로 판정하기 시작한 것**이다.

## 8. 범위 밖

- `daily_ohlcv` 의 US 커버리지 확대 — §2 의 이유로 비용이 크고, §3.2 측정 결과 SPY 로
  충분하므로 **추진하지 않는다**. 다른 목적(US 섹터 상대강도 등)이 생기면 재검토.
- 누적 집중도 신호(§4.2) — 별도 이슈가 필요하면 그때 측정부터 한다.
