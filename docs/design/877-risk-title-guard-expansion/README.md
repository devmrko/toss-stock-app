# 설계서: 리스크 제목 가드 확장 (#877)

> **상태**: Approved · **작성**: [AI] Architect · 2026-10-08
> **추적성** — Redmine: #877(#869·#872 보완) · 구현: `TitleGuard`,
>   `CatalystQualifier`, `RiskEventDetector` ·
>   테스트: `TitleGuardTest`, `CatalystQualifierTest`, `RiskEventDetectorTest`

## 1. 목적 (Why) — 측정된 구멍

#869 의 `TitleGuard.lossSide` 는 **적자·영업손실·어닝쇼크만** 본다.
전체 61,521건 중 **종목코드가 붙은** 기사의 리스크 키워드 빈도:

| 유형 | 건수 | 결정론적 가드 |
|------|------|---------------|
| **유상증자 / 전환사채 / 신주인수권** | **99** | **없음** |
| 상폐 / 거래정지 / 관리종목 / 감사의견 / 회생 / 파산 | 10 | 없음 |
| 감자 / 자본잠식 | 7 | 없음 |
| 횡령 / 배임 / 분식회계 | 1 | 없음 |
| 적자 / 영업손실 / 어닝쇼크 | 16 | **있음** |

**유상증자가 적자보다 6배 많은데 가드가 없다.**

그리고 LLM 의 `riskFlag` 는 라이브 실측에서 facts 있는 321건 중 **6건만** 채워졌다
(98% 생략). 프롬프트가 "판단 안 서면 생략"이라 의도된 동작이지만, 결과적으로
**유상증자는 사실상 무방비**다.

### 1.1 왜 심각한가

#865 자격 게이트는 **금액이 제시된 확정 사실**을 통과시킨다.
`에피소드컴퍼니, 140억원 제3자배정 유상증자` 는 `confirmed=true`,
`materialAmount=true` 를 만족한다. `riskFlag` 가 생략되면
**희석 사건이 매수 근거로 통과**한다. #872 `RISK_EVENT` 매도도 같은 이유로
발화하지 않는다 — 보유 중 유상증자가 떠도 팔지 않는다.

## 2. 설계 (What)

`lossSide`(boolean) → **`riskFlagOf(title)`(String|null)** 로 일반화한다.
반환값은 #865 의 `riskFlag` 체계와 **같은 어휘**를 쓰므로 호출부가 그대로 재사용한다.

| 반환 | 패턴 | 제외 | 근거 |
|------|------|------|------|
| `DILUTION` | 유상증자, 전환사채, 신주인수권, CB·BW 발행 | 철회·취소·중단(호재) | 원칙 §3-3 "유증/회사채 남발 없음" |
| `IMPAIRMENT` | 무상감자, 유상감자, 자본감소, 자본잠식 | — | 자본·존속 위험 |
| `GOVERNANCE` | 횡령, 배임, 분식회계 | — | 원칙 §3-5 |
| `DELISTING` | 상장폐지, 거래정지, 관리종목, 감사의견 거절·한정, 회생절차, 파산 | 해제(거래정지 해제는 호재) | 존속 위험 |
| `LOSS` | 기존 적자 패턴 | 기존 제외(흑자전환·적자 축소·적자 탈출) | 원칙 §3-2 |

### 2.1 오탐을 막는 패턴 선택

- **`감자` 단독은 쓰지 않는다** — 감자튀김·감자칩·감자 농가 등 식품 기사가 잡힌다.
  `무상감자|유상감자|자본감소|자본잠식` 으로 한정한다.
- **`무상증자`는 매칭되지 않는다** — 무상증자는 호재다. `유상증자` 를 명시하므로 자연히 제외.
- **`증자` 단독도 쓰지 않는다** — 무상증자를 잡는다.
- `철회·취소·중단` 동반 시 DILUTION 제외 — "유상증자 철회"는 호재다.
- `해제` 동반 시 DELISTING 제외 — "거래정지 해제"는 호재다.

### 2.2 평가 순서

심각도 순으로 먼저 걸린 것을 반환한다: `DELISTING` → `GOVERNANCE` → `IMPAIRMENT`
→ `DILUTION` → `LOSS`. 존속 위험이 가장 위다.

### 2.3 호출부

| 호출부 | 변경 |
|--------|------|
| `CatalystQualifier.qualify` | `lossSide` 검사 → `riskFlagOf != null`, 사유에 종류 표시 |
| `RiskEventDetector.judge` | `lossSide` 대신 `riskFlagOf` 사용 |

`lossSide` 는 **공개 메서드로 유지**한다 — #869 테스트가 적자 판정을 직접 고정하고
있고, `riskFlagOf` 의 LOSS 분기가 그것을 위임해 쓴다.

여전히 **차단만 추가**하므로 안전 방향이 단조롭다 — 가드가 틀려도 손실이 아니라
기회비용이다.

## 3. 함수 등재 (Function Registry)

|------|------|------|-----|

## 4. 인수조건 (Acceptance)

1. `140억원 제3자배정 유상증자` 가 `riskFlag` 생략이어도 **매수 차단**된다.
2. 보유 중 유상증자 기사가 나오면 **`RISK_EVENT` 로 매도**된다.
3. `유상증자 철회` 는 차단되지 **않는다**.
4. `무상증자` 는 차단되지 **않는다**(호재).
5. `감자튀김`·`감자칩` 류 식품 기사는 차단되지 **않는다**.
6. `거래정지 해제` 는 차단되지 **않는다**.
7. 기존 적자 가드 동작은 **변하지 않는다**.
8. 라이브 코퍼스 적용 시 정상 호재(수주·공급계약·실적) **오탐 0건**.

## 5. 테스트 계획

`TitleGuardTest`:
- 각 카테고리 대표 제목 → 해당 플래그 (라이브 실제 제목 사용)
- 제외 목록: 유상증자 철회 / 무상증자 / 감자튀김 / 거래정지 해제 → null
- 심각도 순서: 상장폐지 + 적자 동시 → `DELISTING`
- 기존 `lossSide` 테스트 전부 유지(인수조건 7)
- null·빈 제목 → null

`CatalystQualifierTest`: facts 양호 + 유상증자 제목 → 차단, 사유에 `DILUTION`
`RiskEventDetectorTest`: `riskFlag` 생략 + 유상증자 제목 → `DILUTION`

## 6. 리스크 / 되돌리기

| 리스크 | 완화 |
|--------|------|
| 패턴 오탐으로 정상 호재 차단 | §2.1 제외 목록 + 라이브 61,521건 전수 적용 검증(인수조건 8) |
| 보유 중 오탐으로 멀쩡한 포지션 매도 | 같은 검증. 차단만 추가하는 구조라 매수 쪽은 기회비용뿐이지만, **매도 쪽은 실현손실**이라 오탐 점검이 더 중요하다 |

되돌리기: 호출부를 `lossSide` 로 환원(2줄).

## 7. 범위 밖

- 공매도 과열종목·불성실공시법인 지정 — 라이브 코퍼스에 사례가 없어 패턴 정확도를
  검증할 수 없다. 사례가 쌓이면 추가.
- `riskFlag` 프롬프트에 `IMPAIRMENT` 추가 — LLM 어휘 확장은 별건(현재도 비(非)NONE 이면
  전부 차단되므로 동작에 영향 없음).
