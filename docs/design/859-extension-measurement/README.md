# 설계서: 급등 필터 측정 교정 — 최근 저점 대비 실시간 상승률 (#859)

> **상태**: Approved · **작성**: [AI] Architect · 2026-10-08
> **추적성** — Redmine: #859(교정 대상 #838) · 구현: `PriceExtension`(신규),
>   `AutoTradeScheduler`, `AutoTradeProperties`, `application.yml` ·
>   테스트: `PriceExtensionTest`(신규), `AutoTradeSchedulerTest`

## 1. 목적 (Why)
#838 급등 필터는 `PopularityChecker.priceMovePct`(**일봉** 최신종가 vs 전일종가)를 쓴다.
그런데 매수 판단은 **장중**에 일어난다 — 장중엔 오늘 일봉이 안 닫혀 있어서 그 값은 어제 것이거나
중간에 덮인 부분값이다. **"지금 이 순간 이미 N% 올라있다"는 사실 자체를 측정하지 못한다.**

또 기준선이 "전일종가"라, 어제 이미 급등한 종목은 다음날 -7~-8%로 보여 그대로 통과한다.

실측(진입 체결가를 직전 완료일 종가/최근 5일 최저와 비교):

| 진입 | vs 전일종가(현행) | vs 5일 최저(제안) | 결과 |
|------|------------------|------------------|------|
| 안랩 1차 | +14.03% | **+20.5%** | -6.71% |
| 안랩 2차 | **-7.64%**(통과) | **+10.6%** | -7.91% |
| LG전자 1차 | +8.12% | **+9.9%** | -8.82% |
| LG전자 2차 | **-8.80%**(통과) | +0.2% | -1.41% |
| 포스코퓨처엠 | **-5.4%**(통과) | **+11.9%** | -3.83% |
| 삼성SDI | **-1.4%**(통과) | **+10.7%** | -2.11% |
| 동국제약 | -5.7% | +3.3% | **+6.02%** |
| 유한양행 | +2.6% | +4.5% | **+0.79%** |
| 현대모비스 | +0.4% | +2.8% | **+0.75%** |

전일종가 기준은 손실 6건 중 4건을 통과시킨다(분별력 없음). **5일 최저 기준은 수익 3건이 전부
+4.5% 이하, 손실 5건이 +9.9%~+20.5%로 깨끗하게 갈린다**(예외 1건 LG전자 2차 +0.2%는 손실도
-1.41%로 거의 본전).

## 2. 범위
- **포함**: 일봉 기반 `priceMovePct` 판정을 "최근 N거래일 최저 종가 대비 **실시간 체결가**
  상승률"로 교체. `extreme-move-pct`(8.0, 당일변동 의미) → `max-extension-pct`(6.0, 저점대비
  의미) + `extension-lookback-days`(5)로 설정 교체.
- **제외**: `PopularityChecker.priceMovePct` 자체(인기 판정·로깅용으로 계속 사용 — 의미가 다름),
  촉매 면제 로직(#855/#857 그대로).

## 3. 인수조건
- [ ] 최근 N거래일 최저 종가 대비 현재가 상승률 ≥ `max-extension-pct` 이고 촉매 면제가 아니면 매수 보류.
- [ ] 측정 불가(일봉 없음/현재가 없음)면 이 필터로는 막지 않는다(현재가 없으면 어차피 뒤에서 걸림).
- [ ] 현재가 조회를 필터보다 앞으로 이동(PriceCache 캐시라 추가 부하 미미).
- [ ] 실측 회귀: 안랩1차(+20.5%)·안랩2차(+10.6%)·LG1차(+9.9%)·포스코(+11.9%)·삼성SDI(+10.7%) 차단,
      동국제약(+3.3%)·유한양행(+4.5%)·현대모비스(+2.8%) 통과.

## 4. 함수 명세
| 함수 | 책임 | 시그니처 | 복잡? |
|------|------|----------|-------|
| `PriceExtension.pctAboveRecentLow` | 최근 N일 최저 종가 대비 현재가 상승률(순수) | `static Double pctAboveRecentLow(List<DailyOhlcv> rows, BigDecimal currentPrice, int lookbackDays)` | 단순 |

알고리즘: rows를 날짜 오름차순 정렬 → 마지막 min(N, size)개의 `close_p` 중 최저값 low →
`(currentPrice - low) / low * 100`. rows 비었거나 currentPrice null이거나 low ≤ 0 → null.

## 5. 엣지케이스
- 일봉이 N개보다 적으면 **있는 만큼**으로 계산(막지 않음) — 신규상장 등.
- low가 0 이하(이상치) → null(판정 보류).
- 측정 불가(null) → 필터 미적용(fail-open). 이 필터는 "과열이면 막는" 추가 안전장치이지
  매수의 필수 조건이 아니며, 데이터 결손으로 전 종목 매수가 멈추는 쪽이 더 위험하다.

## 6. 테스트 계획
`PriceExtensionTest`: 정상 계산 / 저점이 중간일 때 / N보다 적은 데이터 / 빈 목록 → null /
현재가 null → null / 현재가가 저점보다 낮을 때 음수.
`AutoTradeSchedulerTest`: 기존 "급등+촉매없음 → 보류" 테스트를 새 기준으로 갱신.

## 7. 리스크
- 임계값 6.0은 n=9(수익3/손실6) 기반 **잠정값** — 한 주치 데이터, 같은 장세라 과적합 위험.
  매 진입 로그에 이 수치를 남겨(기존 BuyRationale의 "인기:가격"과 별개) 추후 재조정한다.
- 저점 대비 기준은 하락 추세 종목을 상대적으로 통과시키는 성질이 있다(저점이 계속 낮아지므로).
  하락 추세 자체는 기존 상대강도 체크에서 거른다.
