# 함수 설계서: `FxRateCache.usdKrw` (#886)

> **부모 설계서**: ./README.md · **상태**: Draft
> **작성**: [AI] Architect · **구현**: `autotrade/FxRateCache.java:usdKrw`
> **테스트**: `autotrade/FxRateCacheTest.java`

## 1. 시그니처

```java
public BigDecimal usdKrw()
```

## 2. 책임 (단일 책임, 1줄)

USD/KRW 환율을 TTL 캐시와 함께 돌려준다 — 모르면 **null**(호출부가 US 매수를 보류한다).

## 3. 입력

파라미터 없음. 외부 입력:

| 출처 | 내용 |
|---|---|
| 야후 `v8/finance/chart/KRW=X?range=5d&interval=1d` | 일별 종가 배열. 마지막 유효값을 쓴다 |

Toss API 에 환율 엔드포인트가 없다(코드 확인). 야후 `chart` 는 앱이 이미 지수 수익률
(`ValuationClient.getIndexReturnPct`)과 US 일봉 대조에 쓰는 엔드포인트라 새 의존성이 아니다.

## 4. 출력

- **반환**: 환율(예: `1340.78`) 또는 **null**(조회 실패·응답 이상·값 비정상).
- **부수효과**: HTTP 1회(캐시 미스 시), 캐시 갱신, 로깅.

## 5. 동작 / 알고리즘

```
1) 캐시에 유효 항목 있으면 그 값을 반환(성공 TTL 1시간 / 실패 TTL 1분)
2) 야후 chart 호출 (타임아웃 8초)
3) close 배열의 마지막 non-null 값을 꺼낸다
4) 정상 범위 검증: 500 < rate < 5000   → 벗어나면 null
5) 캐시에 저장하고 반환 (실패도 null 로 캐시 — 틱마다 재시도해 외부를 때리지 않도록)
```

### TTL 근거

| 구분 | TTL | 왜 |
|---|---|---|
| 성공 | **1시간** | 실측 최근 5일 1,339.1~1,343.8(변동 0.35%). 슬롯예산 60만원에서 0.35% 는 2,100원이고 1주 단위 주문에서 수량을 바꾸는 경우가 거의 없다. 틱이 1분이므로 1시간 캐시면 외부 호출이 하루 24회로 묶인다 |
| 실패 | **1분** | 일시 장애에서 빨리 복구. `ValuationClient.FAILURE_CACHE_TTL` 과 같은 값 |

### 정상 범위 검증 근거

환율이 틀리면 주문 수량이 그 비율만큼 틀린다. 야후가 다른 심볼 값이나 1 같은 기본값을
주는 경우를 막기 위해 범위를 건다. 500~5000 은 지난 수십 년 USD/KRW 를 모두 포함하면서
자리수 오류(134.078, 13407.8)는 걸러내는 폭이다.

## 6. 에러 & 실패 모드

| 조건 | 처리 | 반환 |
|------|------|------|
| HTTP 실패·타임아웃 | `log.warn`, 실패 캐시 | null |
| JSON 구조 이상 | `log.warn`, 실패 캐시 | null |
| close 가 전부 null | `log.warn`, 실패 캐시 | null |
| 값이 500~5000 밖 | `log.warn`(값 포함), 실패 캐시 | null |

**예외를 던지지 않는다** — US 매수만 보류되면 되고, KR 경로와 매도 경로(손절 감시)를
막아선 안 된다.

## 7. 엣지케이스

- **주말·휴일** — `KRW=X` 는 FX 라 거래가 거의 연속이지만, 비어 있어도 `range=5d` 안에
  직전 영업일 종가가 남는다.
- **앱 기동 직후 첫 호출** — 캐시 미스 → 외부 1회. 그 사이 US 매수 시도가 있으면
  그 틱은 보류되고 다음 틱에 캐시 적중한다.
- **동시성** — `ConcurrentHashMap` 기반(`ValuationClient` 와 같은 패턴). 동시 미스에서
  중복 호출이 날 수 있으나 무해하다(멱등 조회).
- **환율 급변** — 1시간 캐시 때문에 최대 1시간 묵은 값을 쓴다. USD 예수금 상한이
  과대주문을 막으므로 리스크는 수량이 약간 작아지는 쪽이다.

## 8. 복잡도 / 성능

- 캐시 적중 O(1). 미스 시 HTTP 1회.
- 호출 빈도: US 매수 시도마다 1회 호출하지만 **외부 호출은 시간당 1회**로 묶인다.
