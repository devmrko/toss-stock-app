## 1. 목적 (Why) — 라이브 실측

#865 배포 후 `facts` 가 채워진 321건의 실제 판정 분포:

| 사유 | 건수 | 비율 |
|------|------|------|
| 1. 리스크 이벤트 | 5 | 1.6% |
| 2. 선반영 | 26 | 8.1% |
| 3. 미확정 | 150 | 46.7% |
| 4. 규모 미제시 | 132 | 41.1% |
| **통과** | **8** | **2.5%** |

통과율 2.5%는 목표(10% 미만)를 충족한다. 미확정 46.7%도 **과차단이 아니다** —
150건 중 141건이 `kind=SPECULATION`(전망·추측)으로 의도대로 걸렸다.

문제는 **통과한 8건**이다. 종목 코드가 붙은 것은 2건인데 **둘 다 결함**이었다.

| 기사 | facts | 실제 | 결과 |
|------|-------|------|------|
| `HD현대마린솔루션, 美 엔진기업 '골텐스' 3315억원에 인수` | `isTransaction=true`, `beneficiary=`**`SELLER`** | 3315억을 **지출하는** 인수 주체 | **후보 등록됨**(17:15, 촉매점수 3/4) |
| `갤Z 폴드8 흥행에도…DX부문, 2조 적자` | `riskFlag=`**`NONE`**, `confirmed=true`, `materialAmount=true` | 2조 **적자** | 자격 통과(등급 S2라 등록은 면함) |

`beneficiary` 불안정은 #865 종료 노트에 관측 항목으로 적어둔 그대로 재현됐고, 이번엔
**실제로 후보 등록까지** 갔다. `riskFlag` 가 적자를 놓치는 것은 새로 발견한 결함이다.

### 1.1 원인

둘 다 **LLM 한 필드에 차단 여부를 맡긴** 구조 때문이다. 제목만 보면 정규식으로 확정할 수
있는 사안을 LLM 판단에 의존했다. `beneficiary` 는 같은 기사를 두 번 물었을 때
`BUYER` → `SELLER` 로 뒤집힌 전력도 있다(#865 검증 기록).

> 교훈: **정규식으로 결정되는 것을 LLM 에 묻지 않는다.** LLM 은 "이 기사가 무엇에 관한
> 것인가"에 쓰고, "이 단어가 제목에 있는가"는 코드가 본다.

## 2. 설계 (What)

### 2.1 조치 1 — 결정론적 제목 가드 (`TitleGuard`)

LLM 판정보다 **먼저** 평가한다. 통과를 늘리는 일은 절대 없고 **차단만 추가**하므로
안전 방향이 단조롭다(monotone) — 가드가 틀려도 손실이 아니라 기회비용만 생긴다.

| 가드 | 패턴 | 제외 | 근거 |
|------|------|------|------|
| **BUYER** | `공급받` `납품받` `제공받` `조달받` | — | 수령 = 돈 쓰는 쪽(#860) |
| | `인수` | `인수돼` `인수됐` `인수된` `인수당` `피인수` (피인수는 주체가 매각 측) | 인수 주체가 대금 지출 |
| | `매입` | `자사주` `자기주식` 동반(주주환원) | |
| | `발주` | `발주받` `발주 받` | 발주처 = 돈 쓰는 쪽 |
| **LOSS** | `적자` `영업손실` `순손실` `어닝쇼크` `어닝 쇼크` `적자전환` | `흑자전환` `흑자 전환` `적자 탈출` `적자탈출` `적자 축소` `적자축소` | 원칙 §3-2 핵심사업 흑자 |

**모호한 동사는 의도적으로 넣지 않는다** — `구매`·`도입`·`수입` 은 반대 방향도 흔하다:
"소비자 구매 증가"(우리 매출 ↑), "A사 솔루션, B은행에 도입"(우리가 공급), "수입"(수입/소득).
정밀도가 낮은 패턴은 차단만 하는 가드여도 기회비용이 과해진다.

### 2.2 조치 2 — 구 게이트 후보 풀 재심사

현재 활성 후보 29건 중 대부분이 배포 전 37% 게이트로 들어온 것이다:
`노브랜드 버거 매장 확대`, `캪틴큐 11년 만에 한정 패키지`, `아트 스토어 공개`,
`발행어음 특판`, `질환인식 캠페인`, `LG엔솔 리튬 공급받기로`(구매자).
새 게이트는 **신규 등록만** 거르므로 이 풀은 그대로 남아 매수 대상이다.

→ `valuation_note` 가 `자동발견(` 으로 시작하고 `촉매점수` 를 **포함하지 않는** 후보
(= 구 게이트 등록분)를 비활성화한다. `촉매점수` 는 #865 이후 코드만 기록하므로
**신·구 구분자로 신뢰할 수 있다**.

**자가치유형**이다 — 해당 종목에 여전히 자격 있는 뉴스가 있으면 15분 내
`discovery-cron` 이 새 기준으로 다시 등록한다. 수동 개입·백필이 필요 없다.

수동 등록 후보(`자동발견(` 으로 시작하지 않는 노트)는 **건드리지 않는다** — 사람이 넣은
것이므로 자동 판정으로 뺄 권한이 없다.

#### 안전성 — 후보 비활성화는 매도를 유발하지 않는다 (코드로 확인)

| 경로 | 무엇을 보는가 |
|------|---------------|
| 매수 스캔 `AutoTradeScheduler:178` | `candidateMapper.findActive()` ← **여기서만** 후보 활성여부를 본다 |
| 매도 판정 `AutoTradeScheduler:124` | `newsFadeDetector.hasNewsFaded()` + `isCheapAndRelativelyStrong()` — 후보와 무관 |

보유 포지션의 손절·추적손절·뉴스소멸 매도는 후보 테이블을 참조하지 않는다. 따라서
재심사로 비활성화해도 **보유분이 팔리지 않는다**. 효과는 "더 사지 않는다"뿐이다.

원칙 §4 의 물타기 금지와도 어긋나지 않는다(추가 매수를 막는 방향).

### 2.3 호출 순서

```
CandidateDiscoveryService.refresh()
  ├─ requalifyLegacyCandidates()   ← 조치 2 (신규)
  ├─ addNewCandidates()
  │    └─ CatalystQualifier.qualify(facts, title)
  │           ├─ TitleGuard.buyerSide(title)  → 차단   ← 조치 1
  │           ├─ TitleGuard.lossSide(title)   → 차단   ← 조치 1
  │           └─ (기존 facts 5규칙)
  └─ removeFadedCandidates()       ← 기존 그대로(범위 밖)
```

`qualify` 의 시그니처가 `(NewsFacts)` → `(NewsFacts, String title)` 로 바뀐다.
`title` 이 null/빈값이면 가드는 **통과**시킨다(차단 근거 부재 → 차단 안 함, #865 의
비대칭 null 규칙과 같은 방향).

## 3. 함수 등재 (Function Registry)

| 함수 | 파일 | 책임 | I/O | 비고 |
|------|------|------|-----|------|
| `TitleGuard.buyerSide(String)` | `autotrade/TitleGuard.java` (신규) | 제목이 "대상이 돈 쓰는 쪽"임을 확정적으로 보이는가 | 순수 | → `boolean` |
| `TitleGuard.lossSide(String)` | 동일 | 제목이 적자·손실을 확정적으로 보이는가 | 순수 | → `boolean` |
| `CatalystQualifier.qualify(NewsFacts, String)` | 기존 수정 | 가드 2개를 facts 규칙보다 먼저 평가 | 순수 | 시그니처 변경 |
| `CandidateDiscoveryService.requalifyLegacyCandidates()` | 기존 수정 | 구 게이트 등록분 비활성화 | I/O | 로그로 사유 남김 |

신·구 판별은 **SQL 대신 기존 `candidateMapper.findActive()` 결과를 메모리에서 필터링**한다.
활성 후보는 수십 건 규모이고 `removeFadedCandidates()` 가 이미 같은 목록을 쓰므로, 노트
문자열 매칭 전용 SQL(`LIKE '자동발견(%' AND ... NOT LIKE '%촉매점수%'`)을 새로 두는 것보다
조건이 코드에 드러나 읽기 쉽다. 매퍼 변경 없음.

`TitleGuard` 의 두 함수는 정규식 상수만 보는 단순 술어라 별도 함수 설계서를 두지 않는다
(분기·외부 I/O·비자명 알고리즘 없음). 패턴 목록 자체가 §2.1 표로 설계서에 등재돼 있다.

## 4. 인수조건 (Acceptance)

1. `3315억원에 인수` 류 인수 주체 기사가 LLM 이 `SELLER` 라고 해도 **차단**된다.
2. `2조 적자` 류 기사가 `riskFlag=NONE` 으로 와도 **차단**된다.
3. `흑자전환`·`적자 축소` 는 LOSS 가드에 걸리지 **않는다**.
4. `수주`·`공급계약`·`납품` 등 매출이 생기는 쪽 기사는 BUYER 가드에 걸리지 **않는다**.
5. 구 게이트 등록 후보가 비활성화되고, 자격 있는 종목은 자동 재등록된다.
6. 가드는 **차단만 추가**한다 — 기존에 통과하던 정상 기사를 추가로 막는 경우를
   테스트로 고정하고, 기존에 차단된 기사를 통과시키는 경로는 없다.
7. 수동 등록 후보는 재심사로 비활성화되지 않는다.

## 6. 리스크 / 되돌리기

| 리스크 | 완화 |
|--------|------|
| 가드 정규식이 정상 호재를 막음(기회비용) | 모호 패턴 제외(§2.1), 제외 목록 테스트로 고정. 통과분 주 1회 샘플 점검 |
| 재심사로 후보가 0건이 되어 거래가 멈춤 | 원칙 §0 은 주 1회 거래 전제 — 과소거래는 원칙 부합. 자격 있는 종목은 15분 내 자동 재등록 |
| `촉매점수` 문자열에 의존하는 신·구 판별 | #865 이후 코드만 기록하므로 현재는 유일한 구분자. 포맷 변경 시 이 로직도 함께 고칠 것(주석으로 명시) |

되돌리기: `qualify` 의 가드 2줄 제거(시그니처는 유지해도 무해),
`requalifyLegacyCandidates()` 호출 1줄 제거.
